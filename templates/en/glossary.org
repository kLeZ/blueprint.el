* Filling-in guide — Glossary                                      :noexport:

The glossary disambiguates the language of the domain.  Each term has an operational definition (how it is used in this project, not the encyclopedic definition) and states the source it comes from.

** Domain terms (example)

*** Reversal

Operation that cancels, fully or in part, a payment already authorized.  In the current system it differs from a /refund/: the reversal acts before the settlement with the bank, the refund after it. /Source: interview with the operations manager (2024-03-12)/

*** Reconciliation

Nightly process that compares the transactions recorded in the system with the statement file sent by the payment provider.  It finds mismatches (e.g. payments authorized but not settled). /Source: code — module =reconciliation-service=/

** Technical terms with a specific use (example)

*** Idempotency key

Unique identifier the client includes in every payment request.  In the system it guarantees that retransmissions caused by timeouts do not create double charges.  Unlike the generic REST use, here it is mandatory and stored for 24 h. /Source: architecture decision ADR 0003/
