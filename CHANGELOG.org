* 0.4.1 — 2026-11-02

Fixes to 0.4.0 found in its first real use. ERT suite from 554 to 567 tests.

** Project version
- Writing =blueprint-version.org= is no longer a migration step (ADR-002, D7): the =version-file= step disappeared from the plan as soon as another one was applied, without ending up in =#+BLUEPRINT_MIGRATIONS:=, and on a project already in the current format it counted as "1 migration available" in the dashboard and in CI. The file is written by =blueprint-init= and by every applied migration; in the plan, =v= (=blueprint-upgrade-declare-version=) writes it on request, with the inferred version while steps remain and the package's otherwise, and keeps the recorded migrations.

** Fixes
- Migration plan: =blueprint-project-upgrade= (=C-c b ^=, =u= in the dashboard) failed with =Wrong type argument: stringp, nil= on every project without =blueprint-version.org=, because the starting-format column stayed empty; a step without a format now shows "--".
- Dashboard: the project version comes before the milestone, and the milestone title is cut at =blueprint-dashboard-milestone-width= (new option, 40; nil not to cut it) with the full title in the tooltip. With a long title and the dashboard in a side window, the version was not visible.
- Real accented letters instead of apostrophes in the text the package writes (=blueprint-version.org=, the header of =agenda.org=, the title of the =project-files= step), with a test that checks sources and templates.
- Export: "--" between two letters or digits (for example a repository name like =acme--portal=) stays two hyphens instead of becoming an en dash, in ODT, HTML and LaTeX. Configurable with =blueprint-export-double-hyphen=: =except-words= (default), =always= (en dash everywhere, like Org), =never= (always two hyphens).
- ODT export: captioned figures are anchored as characters and centered, so a figure that does not fit on the page moves to the next one instead of covering the previous one (=blueprint-export-odt-images-as-char=, on by default).

* 0.4.0 — 2026-11-02

A full review of 0.3.0, and compatibility with every earlier version, with optional migration. ERT suite from 501 to 554 tests.

** Project version and optional migrations
- Blueprint reads every format it has ever written again: one file per ADR (until 2026-03), glossary and references written in the data directory (until 2026-09), the 0.3.0 agenda.
- =.blueprint/blueprint-version.org= records the project's Blueprint version and the migrations applied; without it, the version is inferred.
- =blueprint-project-upgrade= (=C-c b ^=, =u= in the dashboard): a plan of the available migrations (14 formats from versions before 0.1.0 onwards) and of the outdated or customized project and user templates; it applies only on request, with a backup in =_archive/= and a git warning.
- The dashboard, the JSON report and =blueprint-ci-validate= show the version and the migrations (effect on the exit code: =blueprint-ci-pending-migrations=).
- New options: =blueprint-upgrade-backup=, =blueprint-upgrade-backup-directory=, =blueprint-upgrade-git-check=, =blueprint-template-status-scopes=, =blueprint-dashboard-show-version=, =blueprint-ci-pending-migrations=, =blueprint-diff-default-base=, =blueprint-agenda-view=, =blueprint-glossary-source-position=.

** Fixes
- CI: =blueprint-sync.el= requires =blueprint-history= and =blueprint-roam.el= requires =blueprint-graph= (byte-compile was red on 29.1 and on snapshot); the test workflow installs Graphviz and the preview test is skipped without =dot=; the byte-compile matrix has =fail-fast: false=.
- =blueprint-add-component= is autoloaded again (the cookie had ended up on the templates' =defconst=).
- Changelog: ADRs outside the export (=:noexport:=, =COMMENT=) are no longer included; the template's sample "ADR 0000" ended up in every =CHANGELOG.org=.
- Agenda: the =:ORIGIN:= link resolves from the agenda file (it was relative to the root, but the file lives in the data directory); IDs use the path relative to the root, so they survive moving the project (0.3.0 IDs are recognized and move to the new format at the first refresh, keeping dates and state); =org-agenda-files= as a string (a list file) is no longer turned into a list of characters.
- Component diff: the default compares with =HEAD=, staged changes included; an empty revision at the prompt is no longer passed to git.
- JSON report: missing owner and tech are =null=, and =included= false is =false= (=json-serialize= wrote ={}=); dependencies are computed even when =blueprint-graph= is not loaded yet.
- Preview: the timer uses the root of the saved file, not the buffer current when it fires; =blueprint--dashboard-svg-generate= honors its =ROOT= argument; a rendering error becomes a message instead of escaping the timer.
- Roam clusters: links are read through the file's nodes (in org-roam =links.source= is a node ID), and =id:= destinations map back to the node's file; a second call no longer fails on a read-only buffer.
- Lifecycle lint: the FIXMEs counted are those of the component documents included in master.org, as in the dashboard.
- Questions: the state of an entry is the marker found (an ANSWERED in prose is no longer "open"); =blueprint-answer-question= offers only list lines, indented ones too, and does not write an empty =[FONTE: ]=.
- Glossary: adding to an empty section no longer fails; entries follow the template's format (definition, then =/Fonte: .../=), including those captured with org-capture (=bg=), which now land as level-2 headings in the first section instead of at the end of the file.
- SVG graph (dashboard, preview, Graphviz backend of =blueprint-dependency-graph=): hyphenated ids (=order-service=) were a DOT syntax error and the graph was not generated; they are now quoted, and a =dot= error is reported.
- Agenda: =blueprint-agenda= opens a view with the deadlines and every open entry (with =org-agenda-list= the undated entries did not appear); DEADLINE, SCHEDULED and CLOSED on a single planning line (the second line was not planning, and the date was lost at the next refresh).
- Roam: similarity with org-roam's real schema (tags per =node-id=, level-0 file node); the "In comune" column shows only what is shared.
- Diff: only lines inside hunks are content; "questions resolved" is the net of the ANSWERED lines; files not yet added to git appear as new files.
- Deleting the first component of a section: no leftover page break at the top of the section.
- =blueprint-adr-list= no longer lists the template's sample ADR.
- =arc42-enterprise.org= template with the full guide of =component.org= (examples, what to write, diagram templates) plus the enterprise parts; the guide of both explains =#+BLUEPRINT_LIFECYCLE:=.
- JSON report: a =lifecycle= key per component.
- Autoloads on =blueprint-dashboard-svg=, =blueprint-component-diff=, =blueprint-preview-mode=, =blueprint-roam-similar= and =blueprint-roam-clusters=.
- Documentation: AGENTS.md aligned with the code (structure of =blueprint-init=, ADR path, templates, score computation); USAGE without the glossary gap already closed.

* 0.3.0 — 2026-11-01

Completion of the development roadmap (PLAN.org, phase 9 and 10.8). ERT suite from 425 to 501 tests.

** New modules
- *blueprint-history.el*: =blueprint-sync= records score, penalty, words and marker counts in =.blueprint/metrics-history.org= (=blueprint-history-on-sync=, line skipped when the values do not change); =blueprint-metrics-history= (=C-c b x=) draws the score over time as SVG (9.3).
- *blueprint-agenda.el*: the document's QUESTION and FIXME markers (=blueprint-agenda-marker-types=) become TODO entries of =.blueprint/agenda.org=; DEADLINE, SCHEDULED and state survive the refresh; =blueprint-agenda= (=C-c b U=) opens =org-agenda-list= on that file (9.6).
- *blueprint-changelog.el*: =blueprint-changelog-generate= (=C-c b J=) writes =CHANGELOG.org= from =git log= and from the accepted ADRs (9.1).
- *blueprint-diff.el*: =blueprint-component-diff= shows the =git diff= of the component's directory with a summary (files, headings, markers added and removed, questions resolved); always =--no-ext-diff=, because a =diff.external= in the gitconfig would produce an unreadable format; key =d= in the component list (9.7).
- *blueprint-preview.el*: =blueprint-preview= opens the graph colored by health in a side window and turns on =blueprint-preview-mode=, which regenerates it at every save with a debounce of =blueprint-preview-delay= (1 s) (9.10).

** Extended features
- *Lifecycle*: =#+BLUEPRINT_LIFECYCLE: draft|active|deprecated|archived= (default =active=), an axis separate from the =#+BLUEPRINT_STATUS:= scope; =Life= column in the dashboard; the lint warns about an =active= component with FIXMEs or depending on a =deprecated= one (=blueprint-lint-lifecycle-checks=) (9.2).
- *Questions*: optional =[TAG: ...]= tag on the line; =blueprint-answer-question= rewrites the line as =- ANSWERED [date] text [FONTE: ...]=, which no longer counts in health, dashboard and lint; the list shows Tag and State and filters by tag (=t=) and state (=s=); open entries match the QUESTION column (9.12, leftovers of 9.31).
- *Dashboard*: with =CRONOPROGRAMMA.org= or =TODO.org= at the root (=blueprint-milestone-files=) the status line shows the first TODO heading in file order, with its DEADLINE, and the number of open TODOs (9.11); the yellow/green of the graphs follows =blueprint-delivery-score-threshold=.
- *Glossary*: =blueprint-glossary-add= asks for the section and inserts a level-2 heading with a =/Fonte: .../= line; =blueprint-glossary-lookup= also finds entries in the previous format (10.8).
- *Deleting components*: =blueprint-delete-component= removes the component's =#+INCLUDE= lines and headings from the synchronized sections of master.org, and asks for an extra confirmation when other components depend on it (9.13).
- *Enterprise template*: =templates/arc42-enterprise.org= with enterprise context, stakeholders and compliance; =C-u C-c b A= offers it (9.5).
- *org-roam*: =blueprint-roam-similar= (similarity by tags, links and title) and =blueprint-roam-clusters= (components connected by dependencies and links) (9.8).

** CI integration
- =blueprint-ci-export-json= writes =blueprint-report.json= with health, markers, components, dependencies and lint warnings (9.4).
- Test workflow updated with the new ERT files.

** Documentation
- README, USAGE and AGENTS.md updated; new workflow 13 in USAGE; section "Native Org features supported" (9.16).
