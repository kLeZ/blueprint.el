* +Phase 9.0 --- Incremental functional analysis+ ✅
** +9.0 Commands to build functional.org piece by piece (=blueprint-functional.el=)+ ✅
For large components (monoliths, complex services) the empty =functional.org= template is oversized: the user has to fill dozens of sections at once. The new module =blueprint-functional.el= offers three commands to add the single atomic blocks one at a time:

- +=blueprint-functional-add-area=+ --- a level-2 heading under =* Aree funzionali= with an Org anchor =<<comp-area-slug>>= and a =[DA VALIDARE]= placeholder
- +=blueprint-functional-add-feature=+ --- a level-3 heading under an existing area with a full skeleton: purpose, inputs, outputs, business rules, validation rules, edge cases and exceptions
- +=blueprint-functional-add-entity=+ --- a level-2 heading under =* Entità di dominio= with an attribute table and =*** Rappresentazione logica=
- +=blueprint-functional-add-integration=+ --- a level-2 heading under =* Punti di integrazione= with a metadata table (direction, counterpart, protocol, authentication, frequency, SLA) and =*** Formato scambio= with a code block for the exchanged payload or file

The three commands are in the Transient menu as a third row, *Functional*, on the keys =a=, =f=, =e=. =blueprint-command-map= is updated accordingly.

*Insertion technique*: the same hybrid strategy as =blueprint-questions.el= --- =org-element= to find the heading (=:contents-begin=), then =re-search-forward "^\\*{1,N} "= to locate the next sibling or higher heading, and insertion before it (or at EOF). Missing sections (=* Aree funzionali=, =* Entità di dominio=) are created automatically.

- A single list of the document's files (=blueprint-core.el=): =blueprint--document-files= returns =master.org= and the included files, in document order, each once. The path of each =#+INCLUDE:= is resolved against the directory of the file containing it, as Org's exporter does; includes are followed recursively with cycle protection (=blueprint--document-walk=, which also reports missing files). =#+INCLUDE:= lines are found with =org-element=, so commented ones or those inside a block do not count; those inside a non-exported subtree are skipped. A file included as a block (=src=, =example=, =export= or another block name) does not enter, because in the document it is code. The include's value is parsed with a parser of its own (=blueprint--parse-include-value=): =org-export-parse-include-value= does not exist in Emacs 29's Org. Each file's include list is cached under the =includes= KIND of =blueprint--cached-metrics=. =blueprint--master-file= moves from =blueprint-sync.el= to core.
- Documented limits: a file included in part (=:lines=, =file.org::search=) counts in full; a file included twice counts once; =:minlevel= does not change the text and needs no handling; =#+EXCLUDE_TAGS:= applies only to the file declaring it, while the exporter applies the one of =master.org= (and of the included files) to the whole expanded document, and =#+SELECT_TAGS:= is not handled. Without =master.org= the document is not assembled and the files are the documents of every component (those =blueprint-sync= would include), as before: the case of almost all existing tests.
- Rows of the document (=blueprint--document-units=): one per component, with its included documents, then one for every other file of the document (=master.org= itself, glossary, =enterprise/*=, =nfr/*=, references), identified by the path relative to the root. Every file is on exactly one row, so the rows together give the document's health score (invariance test). One row per file rather than a grouping by part: ~RET~ opens the file directly, without another question, and the path already says which part it belongs to.
- Health score (=blueprint-health.el=): =blueprint--files-health-summary= sums the markers of a list of files; =blueprint-health-score= applies it to =blueprint--document-files=, =blueprint--component-health-summary= to the component's included documents. In real use the score went up rather than down once the non-component files were counted, because they add many words and few penalty points; how much of those words is real text and how much is keywords, URLs and table structure is the question of 9.29.
- Pre-delivery check (=blueprint-delivery.el=): =[DA VALIDARE]=, =[DA REVISIONARE]= and =[FINDING]= are counted with the same sum as the health score, so they match the dashboard columns. In real use the totals dropped sharply, because notes, question registers and interview files no longer count.
- Lint (=blueprint-lint.el=): new =blueprint--lint-project=, the only one used by =blueprint-lint=, =blueprint-ci-lint=, =blueprint-ci-validate= and the pre-delivery check (before, there were four identical loops).
